# Budget stress test — 2026-11-26

Question: what happens when a large task does not fit the phase budget?

## Setup

- Same agent harness and model as the main benchmark.
- Task: three phases — normalize CSV + tests, Excel workbook + chart, 5-page PDF + 3 figures.
- Two runs:
  - **normal:** 8 model turns per phase, 24 total;
  - **tight:** 2 model turns per phase, 6 total.
- Independent judge: pytest, `build_all.py`, normalized values, five workbook sheets,
  chart, PDF pages/sections/figures/text, input immutability.

## Results

| Run | Budget | Actual turns | Wall | Self-reported | Extension | Split | Judge |
|---|---:|---:|---:|---:|---:|---:|---|
| normal | 24 | 25 | 4.80 min | 14 | 0 | 0 | PASS |
| tight | 6 | 18 | 3.92 min | 11 | 1 (6→9) | 1 (+2) | PASS |

Neither run stopped at the budget, and neither silently ground through it.

The tight run's decisions, from `PLAN.md`:

- **EXTEND once after phase 2:** remaining work was the PDF build and acceptance;
  the PDF is one artifact, so splitting would ship a half-verified deliverable.
  New budget: +3 turns.
- **SPLIT phase 3 verification (+2):** mechanical checks passed, but the visual gate
  found a flowchart text overflow and a `-50.00` label collision. A figure defect can
  only be closed by code → rebuild → look, so verification was split into
  3a build/mechanical, 3b visual, 3c fix + re-render + re-inspect.

## The measurement lesson

Self-reported turns are unreliable:

- normal run: reported 14, actual 25;
- tight run: reported 11, actual 18.

The agent was counting phase steps/tool batches, not model turns. The skill now says:
use the harness step indicator or session stats; if unavailable, use tool calls + wall
time as an `estimated` proxy with a 1.5× margin. Never present a self-estimate as exact.

## Conclusion

The budget is a checkpoint and circuit breaker, not a hard stop. A large task may
overrun, but only with a written EXTEND/SPLIT/HANDOFF decision and a complete,
verified deliverable. Silent grinding and half-delivery remain failures.
