# Lean Run benchmark — 2026-11-26

> Earlier skill versions. For the current skill, see
> [`2026-11-26-latest.md`](2026-11-26-latest.md).

Author-measured, single machine, one model, three tasks. Numbers are directional,
not a guarantee.

## Setup

- Agent harness: OpenCode
- Model: `deepseek-v4.1-flash` for both arms
- Two fresh subagents per round:
  - **control:** plan → strict TDD → full suite after changes → self-review
  - **lean:** one recon batch → batched edits → narrow checks → final gate (the requirements matrix and delivery gate were added after round 3)
- Independent judge for every round: file outputs, workbook values, QUBO identity,
  PDF sections, and input immutability. Acceptance criteria were fixed in each
  `TASK.md` before the run; the judge script was written before scoring the outputs.
- Test counts are not comparable across arms and are omitted from the table.

## Results

| Metric | Round 1 CSV | Round 2 Excel | Round 3 QUBO + PDF |
|---|---:|---:|---:|
| Control turns | 19 | 19 | 80 (two runs) |
| Lean turns | 8 | 9 | 24 (one run) |
| Control wall time | 1.97 min | 3.68 min | 10.87 min |
| Lean wall time | 0.86 min | 1.32 min | 3.09 min |
| Turn reduction | −58% | −53% | n/a* |
| Wall reduction | −56% | −64% | n/a* |
| First-pass accepted | both yes | both yes | both no |

\* Round 3 numbers are to the first artifact, not to acceptance. The rebuild was
not measured, so no speed claim is made for round 3.

Round 3's "both no" is the important result:

- **Control** hit its 40-step cap twice and still did not have a PDF after the first
  run; a follow-up was needed.
- **Lean** was technically correct in one run, but its first PDF did not use the
  provided template, had no figures, and left identity placeholders blank. It was
  rejected and had to be rebuilt. The rebuild (14 pages, 6 figures, template cover)
  was outside the 24-turn measurement.

## Lesson

A fast draft that is rejected is not a win. The original `DONE` line was:

```text
python solution.py -> result.json + qubo.csv
python check.py -> RESULT: PASS
```

That covered technical correctness only. It did not cover the delivery contract:
template, figures, placeholders, external evidence, and submission limits.

## What changed after this benchmark

1. **Requirements matrix before lane selection** — `requirement | source | evidence | status`; every row must be PASS.
2. **DONE is the matrix**, not a single command.
3. **Template-first recon** — `template_spec.py` derives headings, placeholders, and image count from the template.
4. **Delivery gate** — render pages, check ordered sections, figures, placeholders, Unicode, and run `delivery_check.py`.
5. **BLOCKED protocol** — if hardware/account/license is unavailable, mark BLOCKED and stop; unattended agents write `BLOCKED.md`.
6. **Budget precedence** — exhausted budget + incomplete matrix = BLOCKED report, not silent grinding.
7. **First-pass acceptance** is tracked; rework counts against speed.

## Caveats

- n=3, one model, one machine.
- Control is a deliberately thorough baseline; real sessions vary.
- The round-3 delivery failure was a requirements-extraction failure, not a math
  failure. Both arms produced the same correct technical answer.
- The new requirements matrix and delivery gate have **not yet been re-validated**
  on round 3. Treat the fix as a hypothesis until a fresh run passes first time.
