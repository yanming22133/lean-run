# Latest-skill A/B — 2026-11-26

This run uses the current skill: requirements matrix, per-phase budgets, delivery
gate, and BLOCKED/HANDOFF protocol.

## Task

Three phases:

1. Normalize a messy 12-row CSV, write `out/normalized.csv`, and add pytest coverage.
2. Build `out/report.xlsx` with five sheets and a `Revenue by Region` bar chart.
3. Build a five-page `out/report.pdf` with four sections and three figures.

## Method

- Same harness and model for both arms.
- Two fresh subagents, launched together.
- Control: plan → strict TDD → full suite after changes → self-review.
- Lean: latest `lean-run` → requirements matrix → per-phase budgets → delivery gate.
- Acceptance criteria fixed in `TASK.md` before the run.
- Independent judge: pytest, `build_all.py`, normalized CSV, workbook values/chart,
  PDF pages/sections/figures/text, input immutability.

## Quality

Both arms passed every judge check:

- 8 normalized rows, exact IDs and values;
- five workbook sheets, exact region/month values, one bar chart;
- five-page PDF, four headings in order, three figures, all required values;
- input CSV unchanged.

Control added more tests (54) and more self-review. Lean added a requirements matrix
and delivery-gate evidence, and delivered 34 tests. The judge found no product
difference.

## What this measures

The headline is **time to accepted delivery** for this task. Both runs were accepted
on the first pass, so no rebuild cost is missing.

The sample is small: one model, one machine, one task family. Use the numbers as a
